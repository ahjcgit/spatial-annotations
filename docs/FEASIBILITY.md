### Experimental native SDK unblock procedure

For a **separate research branch**, acquire the licensed RayNeo OpenXR ARDK 1.1.2 and extract `OXR/Runtime/Plugins/Android/RayNeoSDK-client.aar` and `RayNeoOpenXRLoader.aar` into that repository's `vendor/rayneo-sdk-1.1.2/`. Follow its pinned [vendor instructions](https://github.com/AlexSKuznetsov/rayneo-x3-spatial-sdk/blob/f5c3ecf0a794867624efb927f6d5f4f4c71e6f59/vendor/README.md), which validate exact SHA-256 values. Install its required NDK/CMake and build `./gradlew :sample-scene:assembleDebug`. First validate the unmodified sample on the actual firmware; then implement our `SpatialTracker` and a calibrated renderer. Do not claim metric accuracy, stable timestamps, relocalization or cross-device persistence based solely on that sample. Proprietary AARs remain outside version control and redistribution depends on RayNeo's terms.

### Marker library and other dependencies

The baseline uses the real Maven Central artifact `com.google.zxing:core:3.5.3` (Apache-2.0), verified by successful Gradle resolution/build and actual QR decode tests. Its [API documentation](https://zxing.github.io/zxing/apidocs/com/google/zxing/MultiFormatReader.html) provides `setHints`/`decodeWithState`; the [upstream release history](https://github.com/zxing/zxing/releases) shows maintenance releases. ZXing is a mature maintenance-stage decoder, not an actively expanding AR SDK. It needs neither OpenCV native binaries nor Play services. Camera frames remain local. Other shipped open-source dependencies and licenses are listed in THIRD_PARTY_NOTICES.md; the APK's dependency metadata is generated by Gradle.

## Engineering limits and next experiments

The highest-value next step is a physical X3 Pro acceptance run: validate camera acquisition/marker readability, then license/build the Mercury adapter and verify binocular comfort/gestures. Measure frame rate, power/thermal behavior and Wi-Fi reconnects before adding tracking. If the camera's default size is poor, implement a user-selectable camera/size based on enumerated capabilities.

After that, add server migration/rate-limit/account recovery work for longer deployments, improve glasses setup without typing, and validate PostgreSQL under load. Research markerless recognition only with stored per-instance evidence and explicit ambiguity scores. Add proximity filtering as a non-identity hint. World-space AR requires the calibration and timestamp work described in ARCHITECTURE.md; persistent anchors require a separate relocalization demonstration.
